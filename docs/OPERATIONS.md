# Эксплуатационные модули

## Доступ и аудит

Каталог прав и шаблоны ролей: `packages/contracts/src/permissions.ts`. `users.permissions = null` означает явно выбранный шаблон роли; массив задаёт индивидуальный набор в пределах этой роли. Роль также определяет область данных: администратор — портфель, сотрудник — назначенный объект, арендатор — свои договоры. Проверка права и области выполняется на сервере. Права читаются из текущей записи пользователя на каждом запросе, поэтому старый JWT не сохраняет отозванный доступ. Изменять привилегированные роли и права может только пользователь с `permissions.manage`; собственные права через эту форму менять нельзя.

`PUT /api/users/:id` принимает `permissions: string[]`. `GET /api/auth/me` возвращает эффективный список. `GET /api/audit?q=...&entityId=...&offset=0` возвращает страницу по 50 событий, общее количество и параметры страницы; требуется `audit.read`.

Общий аудит записывается вместе с бизнес-изменением в SQL-транзакции. В нём есть снимки до/после, автор, источник и идентификатор запроса. Пароли, секреты, коды входа и содержимое загруженных файлов исключены. Таблицы аудита и актов защищены от UPDATE/DELETE триггером. Обычная транзакция загружает только последние 200 событий, полный журнал читается постранично из PostgreSQL.

## Структура и планы

`GET /api/structure` возвращает `buildings`, `entrances`, `floors`. Для каждого вида доступны POST, PUT `/:id`, DELETE `/:id`. Обновление требует `updatedAt`; занятый узел удалить нельзя. Составные внешние ключи запрещают связи через чужой объект. `units.floor_id` — каноническая ссылка; текстовые подписи в помещении являются обновляемой проекцией структуры. Форма выбирает этаж по ID; импорт табличных помещений разрешает текстовый путь через тот же механизм нормализации.

`POST /api/operations/floorplans/import-dxf` принимает `{content}` и возвращает геометрию, слои и диагностику. Поддержаны LINE, POLYLINE, LWPOLYLINE с дугами, CIRCLE, ARC, TEXT/MTEXT и одиночные INSERT с вложенными блоками. Кривые аппроксимируются; неподдержанные элементы перечисляются. Лимиты: 8 МБ исходного DXF, 15 000 элементов, 100 000 вершин, 12 уровней блоков. DWG и бинарный DXF предварительно экспортируются в текстовый DXF.

План сохраняется обычным POST/PUT `/api/operations/floorplans`: `kind`, `floorId`, `image`, `geometry`, `markers`, `version`. PUT требует актуальную версию. Редактор поддерживает подложку, масштаб, перемещение, слои, создание и редактирование контуров, привязки помещений/оборудования и переходы к открытым заявкам. Экспорт DXF содержит векторную геометрию; растровая подложка и прикладные связи хранятся в проекте.

## ППР

`POST/PUT /api/maintenance/templates[/:id]` — регламенты с инструкцией, чек-листом и возрастающей версией. График `/api/operations/plans` фиксирует версию регламента и собственный снимок инструкции/чек-листа. Обновление шаблона не изменяет уже выданные задания.

Расписание задаётся `recurrence: days|weeks|months|years`, `intervalCount`, `nextDate`, `leadDays` (0–90), необязательной `endDate`. Для календарных месяцев сохраняется исходный день: 31 января → последний день февраля → 31 марта. План может быть приостановлен. Генератор восполняет пропущенные даты без дублей и прекращает график по окончании срока. ППР-заявка содержит дату выполнения, оборудование, ответственного, SLA и обязательный чек-лист; завершение без обязательных пунктов запрещено. Карточка графика показывает историю заданий и их статусы, раздел «Сроки и работы» — календарь.

## Сметы и акты

Справочники `/api/maintenance/materials` и `/api/maintenance/contractors` доступны по POST/PUT. Услуги продолжают храниться в `/api/operations/services`. Смета содержит работы, услуги и материалы с количеством, единицей, ценой без НДС и выбранной ставкой НДС; подрядчик необязателен. Цены из справочника копируются в смету, суммы и налог округляются по строкам до копеек.

`POST /api/estimates`, `PUT /api/estimates/:id` принимают строгий `EstimateInput` из `operations-platform.ts`. Новая запись передаёт `version: 0`. Каждый переход увеличивает версию: POST `/:id/submit`, `/:id/approve`, `/:id/reject`, `/:id/act` принимают текущую `version`; отклонение также требует `reason`. Утверждение требует `estimates.approve`. На согласовании и после утверждения редактирование запрещено; отклонённую смету можно исправить и подать повторно.

Акт выпускается только после выполнения заявки и обязательного чек-листа. Он хранит отдельный неизменяемый снимок строк, сторон, суммы и версии сметы; повторный выпуск запрещён уникальным индексом. Акт доступен для печати и сохранения в PDF через диалог браузера. Выпуск акта сам по себе не регистрирует банковскую оплату.

`tests/platform.test.mjs` — календарь, права, структура, денежные расчёты, DXF и исключение секретов. `tests/api.test.mjs` — полный HTTP-процесс согласования и выпуска акта. `tests/postgres/platform.test.mjs` — переход с заполненной схемы v2, внешние ключи, неизменяемость и постраничный аудит. `tests/browser.mjs` — DXF, редактирование/сохранение плана, справочники, смета, ППР и мобильная навигация.
