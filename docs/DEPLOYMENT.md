# Развёртывание Wirehouse

URL: https://wirehouse.92.118.115.96.nip.io

Отдельный виртуальный хост, проект Docker Compose `wirehouse`, API только на `127.0.0.1:18044`. База не опубликована на хосте. Каталоги `/opt/wirehouse` и `/var/www/wirehouse` принадлежат только этому приложению. Существующие vhost и compose-проекты не используются.

## Доступ и данные

Первоначальные реквизиты находятся локально в `.deploy/access.txt` (600), секреты на сервере — `/opt/wirehouse/runtime.env` и `/opt/wirehouse/.env` (600). В Git секретов нет. Пароль администратора следует изменить после первого входа. Фиксированный OTP и вход без доставки отключены. Остальным пользователям администратор задаёт email и пароль в разделе «Пользователи»; роль арендатора также поддерживает вход по паролю.

`runtime.env` содержит первоначальные значения; после изменения пароля старое значение более не действует. Запуск bootstrap повторно запрещён скриптом. Демоданные не нужно добавлять при обновлении.

## Обновление

1. Локально: `npm run check && npm run test:browser`. Для установки без сборки desktop: `npm ci --ignore-scripts --workspace apps/web --workspace apps/api --workspace packages/contracts --include-workspace-root`.
   На чистой машине установите Chromium: `npx playwright install --with-deps chromium`.
2. Добавить исходники релиза в индекс Git и выполнить `npm run package:release`. Архив `.deploy/release.tar.gz` содержит только рабочие файлы из Git и собранный web; локальные заметки, инструменты и секреты не попадают в образ.
3. Загрузить архив как `/opt/wirehouse/release.tar.gz` и `infra/deploy/update-wirehouse.sh` как `/opt/wirehouse/update.sh`.
4. На сервере: `bash /opt/wirehouse/update.sh YYYYMMDDTHHMMSSZ`. Тег каждый раз новый.
5. Проверить `/health`, вход, основные разделы, журнал и здоровое состояние контейнеров.

Скрипт делает резервную копию, собирает образ, обновляет только контейнеры своего compose-проекта, проверяет API, атомарно переключает статику, проверяет `nginx -t` и выполняет reload. При ошибке возвращает предыдущий образ, статику и собственный vhost. Предыдущие релизы и образы сохраняются. При изменении формата данных необходима отдельная проверенная миграция; откат кода не откатывает базу.

Не выполнять `docker system prune`, не заменять общий nginx.conf, не останавливать чужие контейнеры, не запускать bootstrap на существующей базе.

## Резервные копии и восстановление

`wirehouse-backup.timer` запускается ежедневно около 03:20 по времени сервера. Ручной запуск: `/opt/wirehouse/backup.sh`. Архив содержит PostgreSQL custom dump, каталог /data с файлами, env/compose и путь статического релиза; контрольные SHA256. Копии приватны и содержат секреты.

Контроль восстановления проверен в отдельной временной базе тем же PostgreSQL: createdb → pg_restore --exit-on-error → SELECT → dropdb. Основная база при проверке не заменяется. Восстановление в действующую базу — отдельная обслуживаемая операция с остановкой API, сохранением текущего состояния и согласованием точки восстановления.

Автоматические копии находятся на том же сервере. Для защиты от потери сервера требуется внешнее хранилище; реквизиты не предоставлены. Копии не удаляются автоматически: организуйте проверенную внешнюю копию, затем политику хранения и контроль свободного места. PostgreSQL и файлы снимаются последовательно; для строго согласованного полного восстановления при активных загрузках делайте копию в окно обслуживания с приостановленной записью.

## Эксплуатация

- `cd /opt/wirehouse && docker compose -p wirehouse -f compose.yml -f compose.network.yml ps` (последний `-f` нужен при наличии сетевого override, см. BOTS.md)
- `docker compose -p wirehouse -f compose.yml logs --tail=100 api`
- `systemctl list-timers wirehouse-backup.timer`
- `curl -fsS https://wirehouse.92.118.115.96.nip.io/health`
- `nginx -t` перед любой собственной правкой vhost.
- Сертификат Let's Encrypt; certbot renew и deploy-hook перезагружают Nginx после продления.
- Логи Docker ограничены 3 файлами по 10 МБ на сервис.
- Один API-процесс: PostgreSQL хранит единое JSONB-состояние, Redis не обязателен. Нельзя увеличивать число реплик без переработки слоя данных.
- Telegram и VK настроены для привязки и доставки кодов, см. [BOTS.md](BOTS.md). WhatsApp отключён; SMS/email, платёжные и банковские интеграции требуют отдельных реквизитов.
- nip.io — техническое DNS-имя на базе IP. Для постоянной эксплуатации замените на собственный домен, выпустите сертификат и обновите vhost.
- На хосте устаревшая Ubuntu 18.04; обновление хоста требует отдельного плана для всех соседних проектов.

Исходное состояние соседних сайтов и конфигов сохранено в `/opt/wirehouse/predeploy`. Уже до развёртывания `www.yondex.tech` отвечал HTTP 500; этот проект не исправлялся и его конфигурация не изменялась.

## Требования к релизу

Node.js 24.11+ нужен для общих TypeScript DTO. Новые клиенты передают строгие JSON-типы; старые клиенты с числами-строками или неизвестными полями получат 400. UI и API выпускаются вместе. Данные контроля продления добавляются совместимо к существующему состоянию; старые записи сохраняются.
