# Полная демонстрация по ТЗ · 28.10.2026

Сайт и агент обновлены; [проверенный релиз, артефакты и оставшиеся действия](RELEASE_2026-10-28.md). Рабочая БП ожидает закрытия для обновления CFE и создания демонстрационного набора.

Поручение: завершить недостающие пункты, создать явно помеченные тестовые данные в 1С:Предприятии, провести сквозную проверку и развернуть результат для показа клиенту. Исходное ТЗ — `materials/specification-original.docx`, нормализованные требования — `docs/spec-2026-09.md`. Предыдущие отчеты 18/22.10 остаются историей, не новой приемкой.

## Порядок выполнения

1. Доступ к актуальному VPS с закрепленным ключом, снимок работающего релиза; изолированный PostgreSQL для тестов без production env/volumes.
2. Импорт объектов, помещений, контрагентов/контактов, договоров, приборов и ЛС из БП. Контакт без телефона остается без телефона; учетная запись и права никогда не создаются по совпавшему контакту.
3. Финансовые выписки из реального регистра `Хозрасчетный`: организация + договор + явные счета. Начальный/конечный остаток и начисления/оплаты сверяются в 1С; неизвестная корреспонденция блокирует пакет. При подключенном ЛС учетные суммы не начисляются второй раз в CRM.
4. Нативные тестовые организация/контрагент/договор/номенклатура, расширение предметных данных недвижимости, бухгалтерские операции с пометкой `ТЕСТ WH-DEMO-*`. Повтор запуска использует манифест и не создает дубли.
5. CRM: контекстный вход собственника/арендатора/исполнителя, заявка, согласование платной сметы, фото/чек-лист, приемка/возврат, ППР, документы и уведомления. Принятое показание и акт возвращаются в выбранную БП.
6. Акт в БП, учетное действие и обратная финансовая сверка; исправление исходных записей, версии, дубли/потеря ack/повтор после сбоя; независимость источников и запрет чужого доступа.
7. Регрессия API/PostgreSQL, браузерные сценарии и демонстрация в рабочем контуре; backup, релиз, проверка данных/очередей после перезапуска, коммит и инструкция показа/удаления тестового набора.

- Мобильные web-ресурсы в Chromium: **1/1**, шесть сценариев (два продукта × чужая роль/истекшая сессия/недоступность API). Это не физические Android/iPhone.
- CFE `WirehouseExchange-0.3.0.cfe`: SHA-256 `e165252ad10fc58efffabb5063c6611e0547400a37dc9a79e0ac48d1f129aff7`.

Первый полный HTTP-прогон остановился на тестовом лимите 600 секунд; повтор с достаточным лимитом прошел. В браузерном прогоне обнаружен реальный дефект: таймаут проверки WebSocket-сессии ошибочно означал logout. Исправление проверено отдельным PostgreSQL-тестом. Повтор браузерного сценария с удаленным PostgreSQL показал исчерпание клиентского пула при WAN-задержках. Итоговая проверка использует API рядом с тестовым PostgreSQL и настоящий браузер через SSH-туннель; production-пул этим не меняется. Сбой подготовки тестового launcher отдельно устранен и не выдается за продуктовую приемку.

Браузерный прогон финальной web-сборки прошел: навигация, DXF, каталоги, согласование сметы и печатный акт, ППР/CSV/Excel, канбан/поиск, пользователи, фото/приемка, мобильная раскладка, вход и восстановление соединения. Лог `.local/browser-final-colocated-20261028.txt`.
