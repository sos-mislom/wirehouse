# Правки по документам

Исходники: «Анализ решения.docx» и «wirehouse правки баги и прочее.docx» из Downloads/Telegram Desktop. Документы и их изображения изучены локально; персональные файлы в репозиторий не добавляются.

## Функциональные изменения

| Требование | Реализация |
|---|---|
| Объект → корпус → подъезд → этаж → помещение | Группировка и фильтрация в «Помещениях», поля корпуса/подъезда, этажи, статусы и карточки помещений |
| Визуальная навигация | Загрузка настоящего плана PNG/JPEG, расстановка отметок помещений; переход в карточку, фото по HTTPS. План не генерируется из выдуманной геометрии |
| Портфель арендатора | Договоры и помещения в карточке арендатора, фильтр структуры по арендатору, области доступа по договору |
| Пользователи | Редактирование, роль, объект, специализация, пароль, блокировка и аудит. Блокировка немедленно отзывает доступ действующего токена |
| Заявка и контекст | Помещение, арендатор, договор, оборудование, услуга, ППР, исполнитель и история; проверка согласованности связей |
| Платные/бесплатные услуги | Каталог, базовая стоимость, ставка часа, записи работ и ТМЦ. Ставка записи работ фиксируется при вводе |
| ППР | Регламент, период в днях, следующая дата, ответственный, чек-лист, автоматическое создание задания при запуске и раз в минуту; защита от повторов после рестарта |
| Оборудование | Тип, номер, характеристики, фото, гарантия, стоимость, ответственный и история связанных ремонтов/ППР |
| Ресурсы | Несколько индивидуальных и общих счётчиков, история, тариф, ответственный; общие расходы по площади и дням аренды, сохранение долей и копеек |
| Ответственный за показания | Исполнитель видит «Мои счётчики» и вводит показания в своём кабинете |
| Объявления | Публикация по объекту, аудитория, срок и важность; арендаторы видят объявления и доступные услуги |
| Канбан | Новые, в работе, ожидание, отложены, выполнены, закрыты; перетаскивание и обычный выбор статуса |

## Исправления ошибок

- Занятые/все помещения и подписанные величины в метриках; актуальные числа арендаторов и заявок.
- Собираемость по реальным начислениям и оплатам за подписанный месяц. NOI — поступления текущего месяца минус внесённые операционные расходы. Будущий прогноз обозначен как оценка.
- Платёжная дисциплина и долг по счетам, включая частичные оплаты. Менеджер не получает счета другого объекта того же арендатора.
- Критичные — открытые заявки срочного приоритета. Завершённые обращения не создают активную тревогу; SLA завершён.
- Согласованные подписи месяцев; пояснения OPEX/NOI и нагрузки команды.
- Отмена формы возвращает к исходному экрану; переходы записываются в историю браузера.
- Убраны служебные и дублирующие описания интерфейса, унифицированы контролы, цвета и таблицы.
- Русские способы оплаты и статусы сверки. Сверка показывает весь список расхождений; понятна величина «на проверке».
- Индексация объяснена, обязательные поля отмечены, недопустимые даты и суммы отклоняются. Истёкшие договоры выделяются.
- Последовательные непересекающиеся договоры разрешены; пересекающиеся периоды блокируются.
- Вложения до 100 МБ, серверная проверка; авторы истории; безопасное скачивание активных типов файлов.
- Прочтение уведомления сохраняется между сессиями и перезапусками. Старое прочтение не скрывает новое событие той же сущности.
- Изменение контакта арендатора не разблокирует пользователя.
- Транзакционный откат связанных изменений; повреждённое хранилище не подменяется пустой базой.
- Защита от удаления объектов, помещений, арендаторов и договоров с зависимыми записями.
- Проверка версии в новых эксплуатационных формах предотвращает незаметную перезапись чужих изменений.
- Бургер и адаптация кабинетов; автоматическая матрица размеров экрана в tests/browser.mjs.

## Явные границы автоматизации

- Индексация ставки фиксируется менеджером по условиям договора, автоматического юридически значимого изменения договора нет.
- Распределение ресурсов требует сверки менеджером перед переносом в начисления. Повторного автоматического начисления не происходит.
- Затраты работ не списываются из внешнего склада: это учёт часов и стоимости ТМЦ. Для NOI расходы вносятся в «Расходах» один раз.
- ППР использует календарные интервалы в днях; не реализованы сложные производственные календари и исключения праздников. Пропущенные периоды догоняются порциями до 24 заданий за проход.
- Telegram и VK подключены по предоставленным токенам; безопасная привязка описана в BOTS.md. Оплата, банки и почта требуют отдельных реквизитов. WhatsApp исключён из входа.
- В развёрнутой базе стартовый демонстрационный портфель. Это не реальные финансовые данные организации. Исходные демонстрационные пароли заменены.
- Хранилище PostgreSQL пока содержит единое JSONB-состояние; разрешён один процесс API. Для большой нагрузки необходимы нормализованная схема, миграции и нагрузочное тестирование.
- Системный Ubuntu на сервере устарел; ОС и соседние приложения не обновлялись. API работает в отдельном контейнере Node 24. Переезд на поддерживаемую ОС следует выполнять отдельной миграцией с проверкой соседних сервисов.
