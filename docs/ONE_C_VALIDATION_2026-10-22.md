## Как изолированы проверки

PostgreSQL запущен отдельным временным контейнером `wirehouse-exchange-tests-20261022`, без volumes рабочей системы. Второй временный контейнер исполнял проверяемые исходники, распакованные из отдельного архива, на зависимостях существующего образа API. Оба контейнера имели метку `wirehouse.purpose=exchange-tests`, ограничения памяти/CPU и не получали production env, токены ботов или данные пользователей.

Тесты создавали временные БД `wirehouse_test_*` только в этом PostgreSQL. Доставка Telegram/VK в соответствующих проверках подменена тестовым транспортом. Новый код и миграция 011 не запускались против рабочей БД.

После завершения оба временных контейнера удалены с проверкой их метки; временный архив на VPS удален, SSH-туннель остановлен. Контейнеров с меткой тестового этапа не осталось. Повторный `/health` рабочей CRM вернул `ok`; ревизия осталась `dc9268795bb754a1571edc2e15038e424ebce059`, в рабочей БД по-прежнему 10 миграций.

Первый полный запуск из Windows через SSH-туннель завершился 17/20: были lock timeout в конкурентных проверках и отказ подключения к тестовому API при старте. Прогон перенесен рядом с БД. Первый контейнерный запуск унаследовал `NODE_ENV=production` из образа и дал 18/20 из-за коротких тестовых JWT-ключей; в финальном запуске явно задан `NODE_ENV=test`, код проверок и рабочие ограничения приложения не ослаблялись.

Некоторые старые наборы печатают `PostgreSQL idle connection failed { code: '57P01' }` при `DROP DATABASE ... WITH (FORCE)` до закрытия простаивающих соединений. В финальном прогоне это не привело к провалу тестов; в новом наборе соединения закрываются до удаления тестовой БД.

## Границы доказательств

- Новый код — приемник CRM для объектов/помещений и исправление атомарности. Реальное расширение БП, CFE, периодический обмен и прикладные записи в 1С еще не реализованы.
- Не выполнены сверка бухгалтерских сумм, перенос показания в регистр/документ БП, потеря ack между живыми системами, загрузка реальных данных заказчика и работа с двумя реальными базами.
- Браузерный E2E, физические Android/iOS-устройства, новый APK/IPA и нагрузочные испытания не запускались. UI не изменялся.
- Проверены наличие свежих backup и успешный статус службы; восстановление backup в этом этапе не проверялось.
- `npm audit --omit=dev`: 1 critical для Android Capacitor; исправление и пересборка мобильного приложения остаются в очереди. Сырой отчет сохранен только в `.local/dependency-audit.json`.
