# UI kit

Интерфейс рассчитан на ежедневную работу управляющего недвижимостью: плотные данные, понятные действия, минимум декоративного текста. Страницы используют название раздела; пояснение добавляется только для неочевидного действия или ограничения.

Основа — официальные [принципы Контура](https://guides.kontur.ru/principles/base/layout/), [модуль](https://guides.kontur.ru/principles/base/grid/) и [таблицы](https://guides.kontur.ru/principles/tables/tables/). Реализация собственная, на общих компонентах `apps/web/src/ui/`.

Токены: фон #F6F6F6, поверхность #FFFFFF, текст #222222, вторичный текст #666666, граница #E5E5E5, основное действие #008060. Системный шрифт, обычное начертание кнопок, табличные цифры для сумм. Контролы 36 px на десктопе и минимум 44 px на телефоне; радиус 4 px; отступы кратны 4/8 px. Telegram и VK сохраняют фирменные цвета.

Страница имеет одну явную колонку; только внутренние области задают свою сетку. В биллинге реестр и платёж стоят рядом на широком экране, в чате — список диалогов и переписка. Мобильная компоновка не определяет ширину десктопных элементов. Карточки не получают цветных декоративных полос: цвет обозначает состояние или действие. Прогноз содержит формулу и состав суммы вместо абстрактного графика.

- `Button`: primary — главное действие, secondary — дополнительное, danger — удаление/опасная операция, text — переход, plain — элемент навигации со своим макетом. По умолчанию `type=button`; отправка формы требует явного `type=submit`. Busy блокирует повторное действие.
- `Input`, `Select`, `Textarea`: единая геометрия, видимый фокус и ошибки; мобильный текст полей 16 px. Checkbox имеет свой размер и кликабельную подпись.
- `Field`: подпись связывается с контролом, hint/error через aria-describedby.
- `Alert`: ошибка — role=alert, успех — role=status; текст объясняет действие пользователя.
- `Badge`, `PageHeader`, `Card`, `EmptyState`: состояния, заголовки и пустые выборки.

Основная мобильная навигация — бургер. Таблицы превращаются в карточки через ResponsiveTable; контент и действия переносятся внутри доступной ширины. Проверяем 320/360/390/768/1024 px, сохранение данных при возврате, фокус, отсутствие горизонтального переполнения. Дополнительные настройки и подключение мессенджеров раскрываются только по запросу пользователя.

## Навигация и мобильные сценарии (октябрь 2026)

Рабочие экраны следуют режиму Operate из Impeccable: узнаваемые элементы,
постоянные названия и видимый выбор важнее декоративных приёмов. Из Taste
применяются последовательная типографика и отказ от лишнего визуального шума;
правила маркетинговых страниц к рабочим таблицам не применяются.

- Боковое меню группируется по задачам: Работа, Аренда, Общение, Управление.
  Названия групп обычным регистром; активный раздел отмечен светлой заливкой
  и `aria-current`, счётчики нейтральные. В чате считаются непрочитанные сообщения,
  а не количество диалогов.
- На экранах до 1080 px бургер открывает все разделы. Постоянные нижние переходы:
  Главная, Заявки, Платежи, Чат. Иконка всегда сопровождается подписью.
  Нижняя панель учитывает safe area; контент имеет соответствующий отступ.
  Открытое меню блокирует взаимодействие с содержимым, Escape закрывает его;
  при переходе к desktop блокировка снимается.
- Новый раздел открывается сверху. В списках действия называют сущность:
  «Добавить помещение», «Добавить арендатора», «Добавить договор», «Создать заявку».
- Главная начинается с текущей работы. Три показателя остаются на виду;
  подробный прогноз раскрывается по запросу, включая NOI и долю расходов.
  Команда доступна в разделе «Пользователи».
- В помещениях сначала показывается список. Структура и планы доступны ниже
  в раскрываемом блоке. На странице объекта структура остаётся доступной сразу.
- В заявках «Список / Канбан» показывают выбранное представление. На мобильном
  в эксплуатации один выбор подраздела, без дублирующих вкладок.
- Мобильный чат показывает список или переписку с явным возвратом «К списку чатов».
  На desktop оба столбца видны одновременно.
- Основной текст 15 px, вторичный текст не светлее #666 на светлой поверхности.
  Поля на мобильном 16 px, интерактивные области не меньше 44 px.
  Таблицы сохраняются на desktop; мобильные записи разделены строками без
  дополнительных рамок карточки внутри карточки.

### Референсы и границы переноса

Изучены официальные экраны [нового приложения Т‑Банка](https://www.tbank.ru/finance/blog/new-mb/):
выделение частых сценариев и сокращение содержимого главной. Использованы также
[Admiral UI](https://github.com/admiral-team/admiralui-ios) как пример согласованных
состояний компонентов и [Apple HIG: Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)
для устойчивой навигации с подписями. Это источники паттернов, а не заявление
о соответствии приложения банковским стандартам.

Скачанные изображения и диагностические скрипты хранятся локально в
`.local/design-references/` и `.deploy/`; они не входят в Git и release.
Банковские логотипы, иллюстрации, цвета и эффекты стекла в интерфейс не переносятся.
Проверки выполняются в Chromium с эмуляцией размеров. Проверка на физических
iPhone/Android остаётся отдельной приёмкой.
