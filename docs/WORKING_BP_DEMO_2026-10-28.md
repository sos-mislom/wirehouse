## Выполненный живой прогон

- По одному ЛС видит каждый арендатор; собственность на помещение не открыла финансовый ЛС другого участника. Пользователь без назначения финансов не видит.
- Файл договора по конкретному ЛС доступен его арендатору; собственник без финансового права, исполнитель и посторонний получили отказ. Общий документ, прикрепленный только к договору, не был автоматически раскрыт назначению на один ЛС.
- Показание 120 с демонстрационным изображением прошло проверку инженером; ввод без обязательного изображения и повтор за принятый месяц отклонены.
- Платная заявка: служба/принимающий → смета 122 ₽ → внутреннее утверждение → согласие арендатора → обязательное изображение до → работа/пауза/возобновление → изображение после/чек-лист → возврат → новое изображение результата → повторная сдача → независимая приемка → акт → закрытие. Попытки обойти согласование/фото/принимающего/момент выпуска акта отклонены.
- Бесплатная заявка прошла работу с изображениями, приемку арендатором и закрытие; исполнитель не смог принять собственный результат.
- Отказ исполнителя до начала записан с причиной и запрещает начать отказанное задание. Заявка оставлена в этом состоянии для показа диспетчеру.
- Созданы оборудование, недельный ППР и текущее задание; выполнены мотивированный перенос и замечание исполнителя. CSV импортирован, повторный Excel с тем же кодом графика не создал дубля.
- Отзыв назначения сразу скрыл ЛС в прежней сессии; восстановление сделано новым явным назначением, история отзыва сохранена.
- Удержано ровно одно подтверждение тестового показания после COMMIT в БП. Нормальный повтор получил **5 сообщений, 1 дубль, 0 отказов**; в БП осталось одно показание. Получены также возврат работы, два принятых результата и акт.
- В рабочей БП создан документ реализации **0000-000001**, сумма **122 ₽**, без бухгалтерского проведения. Отдельная явно помеченная ручная операция акта создала реальное движение регистра: локальная выписка БП стала **5 122 ₽**. Налоговые регистры реализации этой операцией не проводятся.

## Ошибки, найденные именно на этих данных

1. Карточка маршрутизированной заявки обращалась к общему списку сотрудников `overview.team`, которого у исполнителя и портального пользователя нет. Названия службы/принимающего теперь возвращает сервер только в контексте доступной заявки; общий список и дополнительные права не раскрываются.
2. При пакетном обновлении двух ЛС неизмененная строка получала ложный конфликт версии: PostgreSQL возвращает время с `.000Z`, а 1С — без дробной части. UTC-время нормализовано перед сравнением; настоящие изменения сумм при той же версии по-прежнему отклоняются. Добавлен PostgreSQL-прогон повторов и смешанного пакета «обновленный + неизмененный ЛС».
3. CLI агента теперь завершает проход с `status=failed` и ненулевым кодом, если хотя бы одно сообщение отклонено; прежде счетчик отказов мог сопровождаться `status=ok`. Проверки Python: **17/17**.

Исправления входят в приложение/агент **0.3.1**; CFE 0.3 менять повторно не нужно. TypeScript/обычные тесты/web build и **22/22** API/PostgreSQL прошли. После выкладки повторен именно исходный отклоненный пакет: `sent=1, rejected=0`. Затем исходное начисление в рабочей БП исправлено до 12 000 ₽; обычный агент снова передал один пакет без отказов. Прямая сверка API и БП подтвердила одинаковые суммы, строки, UTC-время и версию 3. Неизмененный второй ЛС принят в том же пакете без конфликта.

4. На серии входов разных ролей с одного IP найден инфраструктурный дефект: лимит `/api/auth/` учитывал проверки уже существующей сессии и публичный GET onboarding. Из лимита исключены только два GET-маршрута; остальные операции авторизации по-прежнему ограничены. Ответ ограничителя теперь JSON с `RATE_LIMITED`. Настройка применена к vhost Wirehouse, `nginx -t` и reload прошли, контрольные суммы остальных vhost не изменились. С сервера выполнены 25 проверок сессии (401 без токена), 25 onboarding (200), 17 неверных входов (16×401, затем 429 JSON). После изменения все пять ролей прошли браузерную проверку.

## Как показать клиенту

1. На сайте выбрать объект **ТЕСТ WH-DEMO-20261028 Склад**. Под диспетчером открыть **SD-2026-0012**, показать службу/принимающего, согласованную смету 122 ₽, историю паузы/возврата/повторной сдачи и акт **АКТ-2026-000001**. Отдельно есть бесплатная закрытая заявка и отказ исполнителя с причиной.
2. Показать оборудование «Вентиляция», недельный ППР, перенос и замечание; импорт Excel после CSV не создал второй график.
3. У арендатора DEMO-101 открыть `WH-DEMO-20261028-LS`: октябрьская выписка 7 122 ₽, две строки начислений, дата обновления. У совмещенного пользователя доступны помещение DEMO-101 как собственнику и ЛС DEMO-102 как арендатору; финансов DEMO-101 у него нет. У участника без назначений ЛС отсутствуют.
4. Показать принятое показание **120** с демонстрационным изображением и подтвержденную доставку. В 1С найти помеченные организацию/контрагента/два договора и реализацию **0000-000001** на 122 ₽; документ оставлен непроведенным. Изображения показывают тест процесса, а не реальные выполненные работы.
5. Пароли сотрудников находятся только в приватном `.local/working-demo/credentials.json`. Портальные браузерные проверки использовали короткие административно выпущенные сессии; это не клиентский сценарий реального OTP. Перед показом его нужно отдельно подготовить с настоящим телефоном/каналом либо явно назвать административной демонстрацией.

Тестовый набор сохранен для показа. Автоматически удалять его из БП/CRM нельзя: в нем есть связанные документы, проводки, квитанции и аудит. Для уборки нужен отдельный согласованный порядок; исходная DT-копия сохранена, но восстановление ее поверх рабочей базы уничтожило бы все последующие изменения.

## Открытые границы

Нет физических Android/iPhone и доступов Apple/Firebase — пользователь подтвердил их отсутствие. Поэтому release-подписи, IPA, native push и приемка устройств остаются открытыми. APNs/FCM пока требуют реализации и настройки, а не только проверки уже готовой доставки. Реальный телефонный OTP/канал, фактический Excel заказчика, его учетные настройки и приемка пользователей тоже не подменяются тестовыми данными. Проверка других БП/релизов, настоящего серверного кластера и минимального сервисного пользователя остается открытой. Демо не является бухгалтерским проведением реальных операций заказчика.
