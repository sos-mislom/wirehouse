## Созданные данные

Все новые сущности явно помечены `ТЕСТ WH-DEMO-20261028`. В рабочей БП созданы организация, контрагент, **два настоящих договора**, услуга, ручные учетные операции. В регистрах расширения — склад, помещения **DEMO-101 / DEMO-102**, два прибора и два ЛС. Дополнительное помещение/договор создано отдельно от исходного фиксированного набора, с устойчивыми идентификаторами и проверкой тестовой организации.

В production прошли все семь групп из этой БП без ручного сопоставления CRM: объекты, помещения, контрагенты, договоры, приборы, ЛС, выписки. Начальные суммы первого ЛС: **1 000 + 10 000 − 6 000 = 5 000 ₽**; второй ЛС имеет нулевые суммы. Нельзя выдавать этот набор за данные реального арендатора.

Созданы пять изолированных тестовых участников: диспетчер/инженер, исполнитель, арендатор DEMO-101, один человек с ролью собственника DEMO-101 и арендатора DEMO-102, участник без назначений. Импорт бухгалтерского контакта сам пользователей/права не создавал. Доступ назначен явно и ограничен демонстрационным контекстом.

Сотрудники входят настоящим API входа по паролю. Для портальных тестов администратор выпустил ограниченные по времени сессии тестовых пользователей; это **не приемка телефонного OTP через реальный мессенджер**. Пароли/токены/сессии находятся только в приватном `.local/working-demo`, в Git и публичных архивах их нет.

## Выполненный живой прогон

- По одному ЛС видит каждый арендатор; собственность на помещение не открыла финансовый ЛС другого участника. Пользователь без назначения финансов не видит.
- Файл договора по конкретному ЛС доступен его арендатору; собственник без финансового права, исполнитель и посторонний получили отказ. Общий документ, прикрепленный только к договору, не был автоматически раскрыт назначению на один ЛС.
- Показание 120 с демонстрационным изображением прошло проверку инженером; ввод без обязательного изображения и повтор за принятый месяц отклонены.
- Платная заявка: служба/принимающий → смета 122 ₽ → внутреннее утверждение → согласие арендатора → обязательное изображение до → работа/пауза/возобновление → изображение после/чек-лист → возврат → новое изображение результата → повторная сдача → независимая приемка → акт → закрытие. Попытки обойти согласование/фото/принимающего/момент выпуска акта отклонены.
- Бесплатная заявка прошла работу с изображениями, приемку арендатором и закрытие; исполнитель не смог принять собственный результат.
- Отказ исполнителя до начала записан с причиной и запрещает начать отказанное задание. Заявка оставлена в этом состоянии для показа диспетчеру.
- Созданы оборудование, недельный ППР и текущее задание; выполнены мотивированный перенос и замечание исполнителя. CSV импортирован, повторный Excel с тем же кодом графика не создал дубля.
- Отзыв назначения сразу скрыл ЛС в прежней сессии; восстановление сделано новым явным назначением, история отзыва сохранена.
- Удержано ровно одно подтверждение тестового показания после COMMIT в БП. Нормальный повтор получил **5 сообщений, 1 дубль, 0 отказов**; в БП осталось одно показание. Получены также возврат работы, два принятых результата и акт.
- В рабочей БП создан документ реализации **0000-000001**, сумма **122 ₽**, без бухгалтерского проведения. Отдельная явно помеченная ручная операция акта создала реальное движение регистра: локальная выписка БП стала **5 122 ₽**. Налоговые регистры реализации этой операцией не проводятся.

## Ошибки, найденные именно на этих данных

1. Карточка маршрутизированной заявки обращалась к общему списку сотрудников `overview.team`, которого у исполнителя и портального пользователя нет. Названия службы/принимающего теперь возвращает сервер только в контексте доступной заявки; общий список и дополнительные права не раскрываются.
2. При пакетном обновлении двух ЛС неизмененная строка получала ложный конфликт версии: PostgreSQL возвращает время с `.000Z`, а 1С — без дробной части. UTC-время нормализовано перед сравнением; настоящие изменения сумм при той же версии по-прежнему отклоняются. Добавлен PostgreSQL-прогон повторов и смешанного пакета «обновленный + неизмененный ЛС».
3. CLI агента теперь завершает проход с `status=failed` и ненулевым кодом, если хотя бы одно сообщение отклонено; прежде счетчик отказов мог сопровождаться `status=ok`. Проверки Python: **17/17**.

Исправления входят в приложение/агент **0.3.1**; CFE 0.3 менять повторно не нужно. TypeScript/обычные тесты/web build и **22/22** API/PostgreSQL прошли. Повтор исходного финансового пакета и итоговые проверки UI выполняются после выкладки исправлений; до подтверждения их успешными не считать.
