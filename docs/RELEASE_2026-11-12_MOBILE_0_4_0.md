12 ноября 2026. Ветка `klis192/pp_design_v1:feat/mobile-single-app` (`77e2afd`) объединена с актуальным `main` Wirehouse. Сохранены календарь показаний, регистрация приборов, настоящие фотографии, шаблоны документов и обмен с 1С из ноябрьского веб-релиза.

Опубликовано 12.11.2026 в 12:44:06 UTC: [сайт](https://sklad-kontur.92.118.115.96.nip.io), API и веб-исходники `a8bcc28059c0c1b8b83993070b87461dbb6d3afd`, схема базы 18. Последующие изменения этой заметки не меняют опубликованную сборку.

## Изменения

- Одно приложение для арендатора и исполнителя: роль определяет кабинет после входа. Вход сохраняется при перезапуске; учитываются системные панели и вырезы экрана.
- Камера и уменьшение фотографий перед отправкой. Документы и фотографии открываются через системную передачу файла; веб-скачивание сохранено.
- Сохранённые данные доступны при обрыве связи. Комментарий, фото, чек-лист и решение исполнителя могут ожидать отправки в локальной очереди. Очередь разделена по пользователям; подтверждённые действия удаляются из неё.
- Повтор безопасных команд защищён серверными квитанциями. Повтор использует исходный ключ и точное тело запроса, в том числе после обновления версии задания. Повторный вход не создаёт новую область квитанций; актуальные права проверяются до выдачи сохранённого ответа. Просроченная локальная команда старше 23 часов требует внимания пользователя и автоматически не отправляется.
- Убраны повторяющиеся сообщения очереди. Увеличены небольшие зоны нажатия, расширен поиск, исправлены переносы исполнителя и даты документа. Названия категорий и ошибки формы показываются понятным текстом. Исправлена проверка истечения JWT на точной границе секунды.
- Вместо стандартных ресурсов Capacitor — монограмма «СК» и заставка в цветах приложения.

## Развёртывание

Сначала сервер с миграциями `017-idempotency-keys.sql` и `018-push-devices.sql`, затем веб-интерфейс и APK. Перед миграциями создаётся парная копия базы и загрузок; проверяется сохранность старых строк и последовательностей. Старые ссылки загрузок сохраняются. После перехода на схему 18 старый API со схемой 16 автоматически не возвращается.

Выпуск активирован с проверкой неизменности 60 прежних таблиц, 58 последовательностей, старых ресурсов и соседних сервисов. Перед активацией сохранены остановки на изменившемся временном контейнере, неверном формате ссылки базового Docker-образа и разборе вывода резервного копирования. После последней остановки старый API был восстановлен без восстановления базы; продолжение использовало исходную проверенную парную копию после повторной сверки строк, последовательностей и всего каталога загруженных файлов. Дополнительная копия базы и восстановление базы не выполнялись.
