# Обмен 1С 0.2 · релиз 22.10.2026

## Объем релиза

CRM принимает объекты/помещения по ID и версии источника; добавлена миграция 011 с SHA-256 снимка. Исправлен откат частично ошибочного пакета в PostgreSQL facade. Машинный API сообщает capabilities и позволяет забирать только поддержанные виды исходящих событий.

Расширение WirehouseExchange 0.2.0 и Windows COM/HTTPS-агент реализуют ЛС БП → CRM; показания, принятые работы, возвраты и акты CRM → собственные регистры БП. Квитанция записывается атомарно с прикладными данными. Повторы по messageId и прикладному ключу не создают новых записей; изменение принятого содержимого запрещено. Суммы строк, НДС и итог акта сверяются внутри 1С. Агент согласует типы с установленным CFE и не подтверждает неизвестные события.

Бухгалтерские документы расширение не создает и не проводит. Регистр `WH_WorkEvents` хранит неизменяемую историю, допускающую доставку событий в другом порядке. Для бухгалтерского отражения нужны организация, счета, номенклатура, НДС и согласованный процесс обработки этой истории.

## Состояние рабочей БП

Новая read-only инвентаризация через COM: **организаций=0, договоров=0, проводок=0, реализаций=0, банковских поступлений=0, контрагентов=4**. Команда `scripts/inspect-one-c-data.py` выполняет только агрегатные SELECT и чтение метаданных, бизнес-записи не выгружает. В счетчики включены все записи, включая непроведенные/помеченные на удаление.

По этим данным нельзя определить фактическую аналитику расчетов или сверить начисления и оплаты. Следующий финансовый этап: заполненная организация и договор аренды → явные source-bound соответствия CRM → выбор счетов/субконто → выписка одного месяца из регистра БП → сверка остатков, оборотов и корректировок → повтор и изменение версии. Для договоров/контактов не используются совпадения по имени и фиктивные телефон/email.

## Развертывание и границы

Скрипт обновления сохраняет прежние релизы, образы, backup и vhost; добавлена блокировка одновременных обновлений. Архив пакуется из закоммиченного дерева, `REVISION` точно определяет исходники. Старый API отклоняет новую миграцию, поэтому обратное переключение образа требует отдельного решения по схеме/восстановлению.

Рабочая БП не изменена, CFE в ней не установлен, задание Windows не установлено, производственный источник обмена не создан. CFE и сквозные записи проверены в отдельной синтетической БП. Это релиз CRM и готового интеграционного среза, а не завершенный промышленный обмен всех групп ТЗ.

Остаются автоматический экспорт всех справочников БП, финансовая витрина, учетное оформление актов, история смены ЛС прибора, форма настройки расширения, минимальные права сервисного пользователя и запуск после выхода из Windows, пилот с двумя заполненными базами. Мобильные приложения и нагрузка этим релизом не проверяются.
