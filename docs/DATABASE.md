# PostgreSQL: схема и эксплуатация

## Модель

Приложению требуется PostgreSQL 16+ с расширением `btree_gist`. Рабочие данные хранятся в 34 таблицах схемы `warehouse`. Простые поля имеют SQL-типы, а вложенные чек-листы, распределения и отчёты импорта хранятся в JSONB-полях своих записей.

SQL-миграции версионируются и проверяются по SHA256. Применённый файл не редактируют: каждое изменение схемы оформляют новым файлом и добавляют в список `migrations`. API запускается только при точном совпадении применённых версий и контрольных сумм.

## Новая установка

1. Создать отдельную базу и задать `DATABASE_URL`.
2. Выполнить `npm run db:migrate`.
3. Задать `INITIAL_ADMIN_NAME`, `INITIAL_ADMIN_EMAIL`, `INITIAL_ADMIN_PASSWORD` длиной от 16 символов и один раз выполнить `npm run db:create-admin`.
4. Запустить API и проверить `/health`: `databaseBackend` должен быть `postgres`, `databaseSchema` — `relational-v3`.

Команда создания администратора работает только с пустым списком пользователей и не создаёт тестовые объекты, договоры или аккаунты.

## Обновление

`update-wirehouse.sh` сначала собирает образ, затем останавливает только API Wirehouse, делает согласованный `pg_dump -Fc` и копию файлов, применяет миграции и запускает новую версию. Статика переключается после успешной проверки здоровья. Скрипт не меняет общий `nginx.conf` и не управляет соседними контейнерами.

Перед публикацией запускают `npm run check`, `npm run test:postgres` и браузерные сценарии с `TEST_POSTGRES_URL`. Для тестов нужен отдельный PostgreSQL с правом создавать временные базы. Тесты создают базы со случайными именами и не очищают базу из `TEST_POSTGRES_URL`.

## Проверки и восстановление

- `npm run db:status` проверяет полный список миграций и их SHA256.
- `DATABASE_POOL_SIZE` — целое от 1 до 50, по умолчанию 8 соединений на процесс.
- Подключение ограничено 5 секундами, SQL-запрос — 30 секундами, ожидание блокировки записи — 10 секундами.
- Резервная копия содержит всю базу и загруженные файлы. Восстановление проверяют в отдельной базе командой `db:status`, сверкой количеств и контрольными запросами.

Транзакция использует одно соединение пула, как требует [node-postgres](https://node-postgres.com/features/transactions). Межпроцессная координация использует [транзакционные advisory locks PostgreSQL](https://www.postgresql.org/docs/16/explicit-locking.html#ADVISORY-LOCKS).
